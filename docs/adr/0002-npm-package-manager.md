# 0002. npm як пакетний менеджер

## Контекст і проблема

На чистому клоні встановлення має бути відтворюваним і не вимагати ручних кроків
(spec.md, крит. 5, 6). Потрібно обрати пакетний менеджер і спосіб фіксації версій.

## Чинники рішення

- Нуль ручних кроків після клонування, крім встановлення Node і make.
- Точно відтворюване дерево залежностей.
- Невеликий проєкт: швидкість встановлення не критична.

## Розглянуті варіанти

- npm + `package-lock.json`, встановлення через `npm ci`
- pnpm
- Yarn

## Рішення

Обрано «npm», бо він постачається разом із Node, а `npm ci` встановлює рівно те, що в
lock-файлі, і падає за розбіжності з `package.json`.

### Наслідки

- Добре: жодних додаткових інструментів; `make install` = `npm ci`.
- Погано: npm «піднімає» пакети в спільний `node_modules`, тож код може імпортувати
  неоголошену транзитивну залежність. Це компенсує правило dependency-cruiser
  `no-non-package-json` (ADR-0006).

### Підтвердження

У репозиторії є лише `package-lock.json` (немає `pnpm-lock.yaml` чи `yarn.lock`);
`make install` на чистому клоні проходить без інших кроків.

## Плюси й мінуси варіантів

### npm

- Добре: вбудований; стандарт для курсу.
- Погано: менш суворий щодо неоголошених залежностей.

### pnpm

- Добре: суворе ізольоване дерево, швидкість, економія диска.
- Погано: на чистому клоні потрібен `corepack enable` або глобальне встановлення — ручний
  крок, заборонений крит. 6.

### Yarn

- Добре: швидкий, workspaces.
- Погано: та сама проблема ручного вмикання; жодних переваг для нашого розміру.
