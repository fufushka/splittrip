# 0016. Залежності: composition root + AsyncLocalStorage для контексту запиту

## Контекст і проблема

Лаба вимагає без протягування параметрів передати ініціалізовані ресурси (пул БД),
користувача-ініціатора й business-process ID, причому ID має автоматично потрапляти в кожен
лог з будь-якого рівня (spec, «Шари і контекст», крит. 5). Залежності бувають двох видів:
**на весь процес** (пул, репозиторій, клієнт Auth) і **на запит** (`userId`, `processId`).

## Чинники рішення

- Сервіси й репозиторії не приймають параметрів БД, користувача, `processId`.
- Домен (`trips`) не імпортує `node:*` і фреймворки (architecture.md, правило 4).
- Тести підмінюють сховище (`memory` / `postgres`) без зміни коду сервісів.
- Мінімум нових залежностей і «магії» в рантаймі.

## Розглянуті варіанти

- Composition root (фабрики з замиканнями) + AsyncLocalStorage у модулі `context`
- DI-контейнер awilix зі scoped-контейнером на запит
- Effect (Context / Layer)
- Явні параметри (`ctx` першим аргументом кожної функції)

## Рішення

Обрано **composition root + AsyncLocalStorage**:

- Ресурси процесу створює `main.ts` один раз і передає у фабрики:
  `createTripService({ repo })`, `createPostgresTripRepository({ sql })`.
- Контекст запиту — модуль `context`: `runWithContext({ processId, userId }, fn)` викликає
  `http` один раз на запит (hook `onRequest`); будь-який рівень читає `currentUser()`.
- Логер — `context.log`: pino `mixin` додає `processId` і `userId` з поточного контексту до
  кожного рядка, тож `log.info()` у сервісі чи `storage` нічого не передає.

### Наслідки

- Добре: сигнатури сервісів — лише бізнес-аргументи; новий наскрізний атрибут додається в
  одному місці (`context`).
- Добре: залежності процесу видно в одному файлі `main.ts`, без реєстрації за рядками.
- Погано: AsyncLocalStorage — неявна залежність: функцію, що читає `currentUser()`, не можна
  викликати поза `runWithContext` (кидає помилку — це перевіряється тестом).
- Погано: модуль `context` використовує `node:async_hooks`; доменний `trips` залежить від
  нього, тож правило 4 уточнюється: `trips` може імпортувати `context`, але не `node:*`.

### Підтвердження

Крит. 5: тест перевіряє, що логи роута, сервісу й `storage` одного запиту мають однаковий
`processId`. C6: `node:async_hooks` — лише в `context`.

## Плюси й мінуси варіантів

### Composition root + AsyncLocalStorage

- Добре: без залежностей; стандарт Node; працює через `await` і таймери.
- Погано: неявність контексту; невелика ціна продуктивності ALS.

### awilix

- Добре: автоматичне зв'язування, scoped-залежності на запит.
- Погано: реєстрація за іменами рядків, помилки зв'язування — лише в рантаймі; для 6 модулів
  контейнер дає більше церемоній, ніж користі.

### Effect

- Добре: типізовані залежності й помилки в сигнатурі, жоден ресурс не забути.
- Погано: інша модель програмування для всього коду; великий поріг входу для рев'ю.

### Явні параметри

- Добре: максимально явно, легко тестувати.
- Погано: саме те «протягування», яке забороняє умова лаби.
