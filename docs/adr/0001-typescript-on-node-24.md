# 0001. TypeScript 6.0 (strict) на Node.js 24 LTS, ESM

## Контекст і проблема

Проєкт має бути на Node.js (вимога курсу). Потрібен статичний аналіз (spec.md, крит. 5;
перевірка C5), а домен оперує грошима, де сплутати суму з довільним числом — реальний баг
(spec-fix-03, п. 1). Треба обрати мову, версію рантайму й систему модулів.

## Чинники рішення

- Статичний аналіз типів як окрема перевірка C5.
- Лінт, що використовує інформацію про типи (ADR-0005), має підтримувати версію компілятора.
- Мінімум інструментів між сирцями й запуском.
- Node.js уже встановлено в автора (v24.14).

## Розглянуті варіанти

- TypeScript 6.0 на Node 24, ESM
- TypeScript 7.0 (нативний компілятор) на Node 24
- JavaScript + JSDoc-типи з перевіркою `tsc --checkJs`

## Рішення

Обрано «TypeScript 6.0 на Node 24, ESM», бо це найновіша версія, яку підтримує
typescript-eslint (`typescript >=4.8.4 <6.1.0` станом на 2026-09-29), а Node 24 LTS
запускає `.ts` напряму завдяки вбудованому стиранню типів.

Налаштування: `strict`, `erasableSyntaxOnly`, `verbatimModuleSyntax`,
`rewriteRelativeImportExtensions`; `"type": "module"`; `engines.node: ">=24"`.
Тести запускаються з сирців, `tsc` збирає `dist/` для запуску й smoke-тесту.

### Наслідки

- Добре: типи — окрема перевірка C5; тести без кроку збірки; одна мова для коду й конфігів.
- Добре: гроші можна зробити окремим типом (деталі — ADR про гроші).
- Погано: `erasableSyntaxOnly` забороняє `enum`, `namespace`, parameter properties —
  замість `enum` використовуються union-типи й `as const`.
- Погано: TypeScript 7 швидший, але перехід відкладено; потрібен новий ADR, коли
  typescript-eslint його підтримає.

### Підтвердження

`make typecheck` (C5) і `make build` (C7) проходять; `package.json` містить `engines.node`
і точну версію `typescript` 6.0.x у `package-lock.json`.

## Плюси й мінуси варіантів

### TypeScript 6.0 на Node 24, ESM

- Добре: повна підтримка typescript-eslint; вбудоване стирання типів у Node 24.
- Погано: повільніший за 7.0 компілятор (для проєкту такого розміру неістотно).

### TypeScript 7.0

- Добре: у рази швидша перевірка типів.
- Погано: typescript-eslint не підтримує — зникають лінт-правила на основі типів.

### JavaScript + JSDoc

- Добре: немає кроку збірки взагалі.
- Погано: громіздкі типи в коментарях, слабший контроль; для курсу про інженерні
  стандарти гірше захищається.
