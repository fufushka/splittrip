## (б) Топ-3 зайві або неправильні залежності

1. **`system` → бінарник `git` під час виконання** (`node:child_process`). Це прихована
   залежність від зовнішнього інструмента: у контейнері без git версія буде `unknown`.
   **Рішення:** лишаємо, бо `APP_VERSION` має пріоритет (spec-fix-01, п. 1), а без git
   застосунок стартує (smoke-сценарій `unknown`). У лабі з деплоєм `APP_VERSION` задається
   під час збірки образу. `child_process` дозволено лише в `system` (правило 5).
2. **`typescript-eslint` → версія компілятора.** Лінтер обмежує TypeScript до `<6.1`, тож
   інструмент якості диктує версію мови. **Рішення:** `typescript: ~6.0.3` у package.json,
   причина — в ADR-0001. Перехід на 7.x — новий ADR, коли з'явиться підтримка.
3. **Дозволене ребро `http → trips` без використання.** Граф в architecture.md дозволяє
   більше, ніж використовує код лаби 1: маршрутів поїздок ще немає. Ризик — «мертвий»
   дозвіл, який ніхто не перевіряє. **Рішення:** лишаємо, бо з лаби 2 ребро потрібне.
   Аудит лаби 2 перевіряє, що `http` імпортує лише `trips/index.ts`.

Перевірено й не є проблемою: усі 10 пакетів з README використовуються; `npm audit` — 0
вразливостей; доменні модулі не мають зовнішніх залежностей (правило `pure-domain`).
