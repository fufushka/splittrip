# spec-fix-03: Лаба 1 — граничні правила домену

## Що і навіщо

Доповнює [spec-fix-02.md](spec-fix-02.md): правила продукту не визначали валюту, округлення,
видалення учасника, помилкові перекази й поведінку закритої поїздки. ШІ запропонував правила
(відповідь на промпт `ai/lab1/003`), автор прийняв їх у промпті `ai/lab1/004`.

## Уточнення

1. **Гроші.** Одна валюта на поїздку, без конвертації. Суми — цілі числа в мінімальних
   одиницях (копійках); дробові числа для грошей заборонені.
2. **Поділ порівну.** Сума ділиться націло між учасниками поділу; залишок у копійках
   розподіляється по 1 копійці першим учасникам за порядком додавання до поїздки
   (100,00 на трьох → 33,34 + 33,33 + 33,33). Сума часток завжди = сумі витрати.
3. **Поділ конкретними сумами.** Кожна частка > 0; сума часток точно = сумі витрати, інакше
   витрату відхилено. Платник може не входити до учасників поділу.
4. **Учасник.** Учасник — запис у межах поїздки, не обліковий запис. Прибрати учасника можна,
   лише якщо він не згадується в жодній витраті (як платник чи учасник поділу) і в жодному
   переказі.
5. **Переказ.** Сума > 0; відправник ≠ отримувач; обидва — учасники поїздки. Переплату
   дозволено (лише змінює баланси). Помилковий переказ можна видалити, поки поїздка відкрита.
6. **Закрита поїздка.** Закриття незворотне. У закритій поїздці не можна додавати, змінювати
   чи видаляти учасників, витрати й перекази.
7. **Запропоновані перекази.** Мінімізують кількість переказів жадібно: найбільший боржник
   платить найбільшому кредитору, доки всі баланси не стануть 0; не більше n − 1 переказу
   для n учасників з ненульовим балансом.
8. **Користувач і поїздки.** Застосунком керує одна людина (автентифікація поза обсягом);
   поїздок може бути багато, кожна незалежна.

## Критерії прийняття

- `architecture.md` відображає кожне правило 1–8 у моделі даних, інваріантах або описі
  зміни даних у відповідному сценарії.
- Правила 1, 2 і 7 як ключові доменні рішення мають ADR (крит. 3 spec.md).
