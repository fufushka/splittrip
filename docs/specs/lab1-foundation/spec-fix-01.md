# spec-fix-01: Лаба 1 — уточнення перевірки стану, сліду ШІ та зміни прийнятих документів

## Що і навіщо

Доповнює [spec.md](spec.md) там, де вона неоднозначна або суперечлива. Розбіжності
виявлено до початку роботи (промпт `ai/lab1/001`), рішення прийнято в промпті `ai/lab1/002`.
`spec.md` не змінюється; за розбіжності між ними пріоритет має цей документ.

## Уточнення

1. **Перевірка стану й версія (до крит. 8).** Застосунок — HTTP-сервіс:
   - `GET /health` → `200`, `{"status":"ok"}`;
   - `GET /version` → `200`, `{"version":"<sha>"}`, де `<sha>` — повний 40-символьний хеш
     коміту, з якого запущено застосунок; якщо його не визначити — `{"version":"unknown"}`.

   Джерело версії: змінна середовища `APP_VERSION`, якщо задана; інакше `git rev-parse HEAD`
   під час збірки або старту. Будь-яка помилка визначення → `unknown`, застосунок стартує.
   Smoke-тест перевіряє: старт; обидві відповіді; формат `^[0-9a-f]{40}$` або `unknown`;
   у робочій копії git — збіг із `git rev-parse HEAD`; без git — `unknown`.
2. **Слід ШІ (до крит. 12).** `ai/labN/NNN-<slug>.md` — дослівний текст промпту автора, без
   відповідей ШІ й коментарів. Кожен коміт, створений ШІ, містить трейлери:
   `AI-Prompt: ai/labN/NNN-<slug>.md` (по одному на кожен промпт, що його породив) і
   `Co-Authored-By: Claude …`. Посилання «промпт → коміти» отримується з історії однією
   командою (див. перелік перевірок), а не вписується в файл промпту вручну.
3. **Зміна прийнятих документів (до «Обмежень» і крит. 13в).** Прийняту spec ніхто не
   редагує — виправлення оформлюється новою `spec-fix-NN.md` поруч. Стандарт змінюється
   окремим комітом, що підвищує його версію й додає запис у журнал змін. ADR не
   редагується — новий ADR отримує статус «замінює ADR-NNNN». Чернетку в усіх випадках
   пише ШІ, автор приймає окремим комітом. До прийняття чернетку можна змінювати на
   прохання автора.
4. **Розташування артефактів (до крит. 2, 7, 10, 13, 14).** Усе, що належить лабі N, —
   у `docs/specs/labN-<slug>/`: `spec.md`, `spec-fix-NN.md`, `architecture.md`, `audit.md`,
   `DEFENSE.md` (окремий на кожну лабу), `reports/` (реальні виводи перевірок). ADR — у
   `docs/adr/`, бо рішення наскрізні для курсу. Кореневий README посилається на DEFENSE
   кожної лаби.
5. **Мова.** Уся документація й повідомлення комітів — українською; ідентифікатори в коді —
   англійською. Формат комітів визначають стандарти.
6. **`make` (до крит. 5).** README описує встановлення `make` там, де його немає за
   замовчуванням (Windows).

## Критерії прийняття

- `spec.md` вміщується в 1 сторінку; суть, розділи й нумерація критеріїв не змінені (diff
  коміту скорочення).
- Кожне уточнення 1–6 відображено в стандартах або коді й перевірено в аудиті поряд із
  критеріями `spec.md`.

## Обмеження

Ті самі, що в `spec.md`.
