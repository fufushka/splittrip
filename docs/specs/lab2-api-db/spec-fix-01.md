# spec-fix-01: Лаба 2 — уточнення після статичного етапу

Статус: прийнято (`ai/lab2/010`).

## Що і навіщо

Доповнює [spec.md](spec.md), [contract.md](contract.md) і [architecture.md](architecture.md).
Під час реалізації статичного етапу (`ai/lab2/008`) AI знайшов три розбіжності у власних
чернетках, які автор прийняв: формулювання критерію, ребро графа й властивість id, без якої
падав API-тест. Четвертий пункт — інтерпретація контракту, яку AI обрав сам (`[AI]`).

## Уточнення

1. **До крит. 1.** «Коміт етапу — раніше за перший коміт `storage`» суперечить
   architecture.md, розд. 1 і 5: memory-реалізація теж живе в `storage`. Читати: коміт
   статичного етапу — раніше за перший коміт **postgres-реалізації** `storage`
   (`src/modules/storage/postgres/`).
2. **До architecture.md, розд. 2.** У графі бракує ребра `http → ids`: `http` генерує
   `processId` як UUIDv7, коли `X-Request-Id` відсутній або небезпечний (spec, «Шари і
   контекст»). Ребро дозволене; решта графа без змін.
3. **До contract.md, розд. 2 («UUIDv7 генерує застосунок»).** Id монотонно зростають у
   межах процесу, зокрема для кількох id в одній мілісекунді (лічильник у `rand_a`,
   RFC 9562, розд. 6.2, метод 1). Без цього `GET /trips` «новіші першими» й курсор
   нестабільні: API-тест списку падав приблизно в 1 з 5 прогонів.
4. **До contract.md, «Ідемпотентність» `[AI]`.** `Idempotency-Key` необов'язковий: без нього
   `POST` виконується без захисту від повтору (як у Stripe). Ключ — 1–255 символів, інакше
   `400`.

## Критерії прийняття

- П. 1: `git log --reverse` — коміт `test(api)` статичного етапу раніше за перший коміт, що
  додає `src/modules/storage/postgres/`.
- П. 2: `npm run boundaries` дозволяє `http → ids` і валить будь-яке інше нове ребро.
- П. 3: `npm run test:unit` — 5000 id з однаковим часом і 10 з часом у минулому зростають
  строго; `npm run test:api` 15 разів поспіль без падінь.
- П. 4: API-тести: `POST` без ключа → `201`; ключ довший за 255 символів → `400`.

Ті самі, що в spec.md.
