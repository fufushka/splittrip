# Стандарти SplitTrip

Власні інженерні стандарти проєкту на весь курс. Кожен стандарт має версію й статус.

| Стандарт | Про що |
|---|---|
| [spec-format.md](spec-format.md) | Формат spec і spec-fix |
| [adr-template.md](adr-template.md) | Шаблон і правила ADR (MADR) |
| [definition-of-done.md](definition-of-done.md) | Коли коміт, PR і лаба вважаються готовими |
| [checks.md](checks.md) | Перелік перевірок: що, як запустити, коли, що блокує |
| [ai-workflow.md](ai-workflow.md) | Правила роботи з ШІ і слід промптів |
| [commits.md](commits.md) | Коміти, гілки, PR |
| [repository.md](repository.md) | Чистий репозиторій, дозволені файли без розширення |

## Як змінюється стандарт

1. Чернетку зміни пише ШІ або автор окремим комітом: версія підвищується, у «Журнал змін»
   стандарту додається рядок із причиною і посиланням на spec-fix чи аудит.
2. Автор приймає зміну окремим комітом `docs(standards): прийняти …`, статус → «прийнято».
3. Прийнятий стандарт ШІ сам не змінює (див. [ai-workflow.md](ai-workflow.md)).

Статуси: **чернетка** (запропоновано, ще не прийнято) · **прийнято**.
