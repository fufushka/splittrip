# Стандарт: робота з ШІ

Версія: 0.4 · Статус: прийнято

## Слід промптів

- Кожен промпт автора зберігається дослівно в `ai/labN/NNN-<slug>.md`: лише текст автора,
  без відповідей ШІ, коментарів і правок (навіть друкарських помилок).
- Нумерація наскрізна в межах лаби (`001`, `002`, …); `<slug>` — 2–5 слів англійською.
- Файл промпту комітиться не пізніше за перший коміт, який цей промпт породив.
- **Виняток — питання допиту ШІ.** Щоб відповіді автора («по 9 пункту ок») читалися, питання
  й варіанти ШІ зберігаються окремо: `ai/labN/NNNa-ai-<slug>.md`, де `NNN` — промпт, на який
  ШІ відповідав. Перший рядок файлу — «Вихід ШІ, не промпт автора». `npm run ai-trace` такі
  файли не рахує промптами.

## Позначення комітів ШІ

Кожен коміт, створений ШІ, закінчується трейлерами:

```
AI-Prompt: ai/lab1/001-structure-and-ai-process.md
Co-Authored-By: Claude <модель> <noreply@anthropic.com>
```

- `AI-Prompt` — по одному на кожен промпт, що породив коміт.
- Коміти, які автор написав сам, трейлерів не мають.
- Посилання «промпт → коміти»: `npm run ai-trace` (перевірка C9 у [checks.md](checks.md)).

## Хто що пише

- **DEFENSE.md** — лише автор, власноруч (DoD курсу §4). ШІ може зробити рев'ю.
- **spec.md** — ШІ пише чернетку лише після допиту: аналізує вимоги, знаходить суперечності,
  ставить уточнювальні питання, пропонує варіанти. Рішення ухвалює автор; його відповіді —
  промпти в `ai/labN/`, на які spec посилається. Пропозиції ШІ, на які автор не відповів
  явно, позначаються в spec як `[AI]`.
- Стандарти, ADR, архітектура: ШІ пише чернетки; автор приймає окремим комітом.
- Обов'язкові дії агента в кожній сесії — [CLAUDE.md](../CLAUDE.md) (короткий виклад цього
  стандарту; за розбіжності переважає стандарт).

## Межі повноважень ШІ

- Після прийняття ШІ не редагує документ; зміна — нова spec-fix, нова версія стандарту або
  новий ADR ([spec-format.md](spec-format.md), [adr-template.md](adr-template.md)).
- ШІ не реалізує spec-fix, нову версію стандарту чи ADR до коміту їх прийняття автором:
  спершу чернетка → прийняття → код. Причина: у лабі 2 код за spec-fix-01–03 з'явився
  раніше за їх прийняття (незалежний аудит, `ai/lab2/012`).
- ШІ не пушить, не створює й не мерджить PR без явного прохання автора в промпті.
- ШІ не обходить hook-и й не послаблює перевірки, щоб коміт пройшов.
- ШІ не додає залежність без «навіщо» в README; для ключових інструментів — ще й ADR.
- ШІ додає до коміту лише явно названі шляхи (без `git add -A` / `git commit -a`) і перед
  комітом перевіряє `git diff --cached --stat`: у коміті — рівно один логічний крок.

## Коли ШІ зупиняється й питає

- Spec неоднозначна, суперечлива або не покриває потрібне рішення.
- Інструкція автора розходиться зі spec — зокрема в назвах файлів, каталогів чи команд.
  ШІ не «виправляє» автора на власний розсуд, а питає й чекає відповіді.
- Реалізація не може виконати критерій без зміни spec чи стандарту.
- Потрібне рішення з реальними альтернативами (кандидат на ADR).

ШІ перелічує знайдені розбіжності явно, до виконання, а не лише в підсумку.

## Аудит виходу ШІ

Кожен «зрізаний кут» ШІ проти spec фіксується в аудиті лаби (розділ DEFENSE або
`audit.md`, якщо його вимагає spec):
промпт (`ai/…`) → фідбек автора → spec-fix / зміна стандарту → коміт виправлення.
